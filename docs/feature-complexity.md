# 功能与复杂度速查

供开发和扩展时定位成本；描述当前实现，不是性能承诺或未来功能清单。
过滤语义见 [过滤、投影与显示流程](filtering-pipeline.md)。改变算法、缓存输入或预算时，同步更新对应行即可。

## 记号与口径

- `N / M`：工作区快照的原始节点 / 关系数；`V / E`：当前计算图的节点 / 关系数。
- `C`：该步骤读取或生成的字符/字节总量；`P`：处理的原始关系证据数；`D`：最大祖先链深度。
- `Map / Set` 按平均常数时间查找估算；字符串处理、序列化和证据展开另计，不能只按最终画面上的节点数估算。
- 时间片、Worker 和 GPU 改善响应性或执行位置，不会自动降低算法复杂度。空间列主要指额外索引和结果，不代表进程峰值内存。

## 关联发现的成本与边界

[输入整理](../apps/siyuan-plugin/src/modules/discovery/reference-graph.ts) 消费提及合成前的
当前投影图。设 `U` 为可用文档数、`R` 为去重后的有向跨文档引用对数、`K` 为匹配候选数。
扫描、归属映射和文档对去重为 `O(V + E)`，稳定文档 ID 排序为 `O(U log U)`；
额外空间 `O(V + E + U + R)`，保留已有边的引用，不复制原始出处。节点/边遍历分批让出主线程，
文档排序和初始数组构建仍是同步步骤。原始图的源过滤与投影成本另计。

[数值查询](../apps/siyuan-plugin/src/modules/discovery/algorithm.ts) 每次在独立 Worker
内建立双向 CSR、支持对象权重和文档权重和，时间与空间为 `O(U + R)`。
对“引用相同资料”，倒排访问数为 `Q = Σ起点 Σ其引用目标 入度(目标)`；
“被共同引用”反转方向。候选计算为 `O(U + R + Q + K log K)`，额外工作区为 `O(U)`。
先计算访问预算，超限拒绝整次查询；不能把前 100 个结果误解成只检查了 100 个候选。
同一文档的重复引用不增加集合大小，通用支持对象按 `1 / log2(2 + 倒排度数)` 降权；
每个起点使用加权 Jaccard，候选取各起点的最佳分数。

查看单个候选时仍需建立 CSR 和权重；再建立候选的支持集合，逐起点求交，
按支持对象权重排序，附加成本为 `O(候选度数 + Σ起点度数 + Σ共同数 log 共同数)`。
每个起点只返回前 50 篇支持文档，分数和共同总数使用完整交集。
主线程按这些文档对查已有边，画布临时高亮最多 2,000 条实际边；
首次映射渲染边身份为 `O(E显示)`，随后按所需证据查索引。

最多 128 个起点文档、5,000,000 次候选倒排访问、前 100 个候选，Worker 超时 60 秒。
候选总数完整报告；证据截断单独提示；预算或超时错误不会包装成完整结果。
Worker 只接收数值端点副本，不传正文、标题或证据；完成、失败或取消后终止。
打开面板期间可复用当前图的主线程归属与端点索引；每次查询冷建 Worker 内索引，
不存储全部文档之间的相似度。关闭会释放查询及索引，过期结果不能覆盖新请求。
图、起点和规则影响结果；颜色、语言、相机、邻域跳数不重算。Worker 调度、复制和
主线程映射仍有成本，这些限制不是任意图下的交互延迟保证。

## 读取复制与渲染准备

块读取按唯一 ID 分页，先在 SQL 中按 ID 分组，再选取每组最大 `rowid` 对应的完整记录。
组内记录数在分页和宿主返回上限前统计，保留唯一节点计数与原始索引行计数两套完整性校验。
分组和范围扫描使用 ID 索引，外层只排序每页最多 1,000 条记录；SQL 查询成本另计。
重复 ID 的多余行数和来源记入有界读取诊断；最大行号仅为确定性取舍，不保证最新正文。

层级布局在当前计算图的 Rust CSR 上执行完整的多源 BFS，时间 `O(V + E)`、输出 `O(V)`，
不可达使用独立哨兵；不复用受深度和数量限制的邻域列表。距离计算复用当前图的 Worker，
以图、起点集合和方向标识请求；语言、颜色、相机和邻域深度变化不重算距离。
按稳定 ID 排列各层最坏 `O(V显示 log V显示)`，坐标占 `O(V显示)`；二维每层一列，三维每层一个平面。
坐标生成和 GPU 位置提交仍在主线程，完整计算不等于任意规模下都能清楚显示所有标签。
切换外观不会重新排列拖动后的节点；重新选择起点、改变方向/计算图/维度、可见节点变化或显式重新分层会重新排列。

数据库补充阶段保留独立节点和边数组，但共享已有的不可变边及其证据；只给复制后的数据库载体节点补充信息，并新建数据库关系。这减少了 `O(M + P)` 次对象/数组分配，节点复制和边数组构建仍是线性的；收益发生在读取和刷新时。

[渲染输入整理](../apps/siyuan-plugin/src/adapters/cosmograph/prepare-graph.ts)仍在主线程分批建立稠密索引、样式列和原始节点/边映射。
[专用 Worker](../apps/siyuan-plugin/src/adapters/cosmograph/graph-preparation.worker.ts)负责标签转义、Arrow 建表和 IPC 编码，只接收渲染列，不复制正文、原始图或关系证据。
字符串列仍有结构化克隆成本，准备阶段独有的数值缓冲区和返回的 IPC 字节使用转移。上传 DuckDB 时还需复制 IPC 字节，因为其接口会转移输入缓冲区；保留原始 IPC 才能安全重试。

Worker 按画布复用；替换正在执行的编码、取消、失败或 60 秒超时都会终止它，后续请求重新创建。它改变计算位置，不降低复杂度，也不保证总准备耗时或峰值内存减少。
源范围和语义投影仍同步执行；即使只显示少量文档，投影仍可能遍历整个原始图。

显示背景直接复用当前计算图的 `eligibleIds`，不再重复展开范围和分配集合；邻域结果只更新高亮，不触发可见图投影。
替换渲染数据时，坐标恢复仍需读取旧布局和新布局，按稳定 ID 合并，时间和额外空间为 `O(V旧 + V新)`。恢复数量在合并时计数，不为诊断再次读取全图坐标；显式 Fit 的布局统计复用它自身所需的坐标读取。

## 自定义集合分组的成本

[集合匹配 Worker](../apps/siyuan-plugin/src/modules/layout-groups/matcher.ts) 接收当前显示节点的 ID 和标题。
启用的集合存在 ID 规则时，还分批扫描原始源图，复制原生包含结构，不复制正文、引用或数据库关系。
设显示节点数为 `V`、源节点／边数为 `N`／`M`、包含边数为 `H`、集合数为 `K`、规则数为 `R`、标题字符总数为 `C`：
输入准备约 `O(V + C)`，存在 ID 规则时另加 `O(N + M)`。Worker 共用源包含索引，每个集合的 ID 子树取并集，
最坏附加成本 `O(K × (N + H))`；可见节点归属扫描约 `O(V × K)`，另加实际文本包含查找及正则执行成本。
标题和正则仅匹配当前节点，不沿包含关系展开。任意正则不保证线性时间，匹配任务在 10 秒后终止；替换输入会终止旧 Worker。
返回一个节点归属数组和每集合的匹配／归属计数，额外空间约 `O(N + H + V + K + R + C)`；逐集合释放展开结果。

规则取并集，计数按节点去重；优先级通过启用集合的数组顺序确定，未匹配节点使用独立哨兵值。
拖动时仅更新插入提示，松手后计算；修改名称、聚拢力度和背景开关不重新匹配。
最多 50 个集合，合计 2,000 条规则和 128 条正则。自动社区与自定义集合互斥运行，
共用现有渲染聚拢及二维背景通道，更新成员不重建遍历拓扑。

## 文档排除的成本

文档排除使用独立的 [匹配 Worker](../apps/siyuan-plugin/src/modules/content-exclusions/matcher.ts)。
每次源／规则／范围／投影或步骤配置变化，分批扫描 `N + M`，复制包含结构、关系端点、完整标题和空状态，不复制正文或引用证据。ID 查找与子树展开约 `O(N + M)`；
标题按唯一归一化标题与规则匹配，普通子串成本依赖字符串长度，正则不能保证线性时间。
每个标题仅缓存命中范围，`R` 为规则数，不保存每个标题的全部匹配规则。三个固定步骤共享一次预览，最多执行一次初始投影和三次步骤投影，成本见上面的投影条目（包含祖先链及出处处理）。
空状态在读取时按正文字符扫描一次，约 `O(N + C)`，筛选时不重复检查正文。连接保留对当前步骤图排序稳定 ID 和边，最坏 `O(V log V + E log E)`，另加并查集合并及 `O(V + E)` 剪枝。权值分 0/1 两轮，但稳定等权次序仍需排序。
额外保留紧凑源数据、投影图、森林和最多三组影响身份；成本随 `N + M + V + E + C标题 + R` 增长，投影生成的祖先出处额外空间另计。
匹配阶段有 10 秒期限；超时、取消或输入替换直接终止 Worker。预览在草稿停顿 400 ms 后独立执行同一任务，
返回源排除 ID 和逐步投影节点差异，详情检索扫描这些身份的展示文字、每页最多渲染 50 行。预览与应用结果不相互覆盖；没有草稿修改时复用已应用结果。

## 文本提及的成本拆分

**已应用规则的关系影响** 仅在详情打开时额外建立一个无排除的提及客户端，复用当前实际结果作另一侧。
对照索引的成本与正文索引相同，额外内存也包含该索引；关闭详情立即释放。结果按有向显示端点做集合差，约 `O(E前 + E后)` 时间和空间，分页只渲染 50 条关系。
名称排除可能暴露其他匹配，所以减少和新增分别计数；任一侧触及索引或输出上限时不宣称完整影响总数。

**排除预览** 使用独立的 [名称目录](../apps/siyuan-plugin/src/modules/mentions/exclusion-preview.ts) 和 [Worker 客户端](../apps/siyuan-plugin/src/modules/mentions/exclusion-preview-client.ts)。首次扫描已有块的标题/属性，分批提取轻量字段，不复制 Markdown 正文；目录构建按名称字符量与名称—节点对应数计。草稿停顿 400 ms 后匹配；简单正则仍约 `O(R × S)`，另加被匹配的名称—节点对应数。规则变化可复用目录；正在运行的旧请求直接终止。预览的 10 秒超时不会终止正式提及索引。

预览为去重名称和原始节点计数，并保留匹配的名称—节点行供分页：额外空间约为名称目录和匹配对应数。分页每次只传 50 行；同一检索条件复用过滤后的行，修改名称/ID 检索条件时扫描匹配行，成本随其字符量增长。它不重新扫描正文，也不估算边数减少量。

1. **词表构建与排除**：读取所有候选标题、名称、别名，普通排除项走哈希索引；正则编译一次，对每个归一化名称缓存判断结果。同名节点仍保留各自身份。若 `S` 是去重名称的总字符数、`R` 是正则数，数字/日期这类固定简单模式的匹配成本约 `O(R × S)`；任意 JavaScript 回溯正则没有统一线性保证。带正则的词表准备阶段由主线程计时，10 秒未完成则终止 Worker；这不限制后续正文预热的总时长。
2. **正文命中缓存**：[多关键词自动机](../apps/siyuan-plugin/src/modules/mentions/matcher.ts)一次扫描正文，避免逐标题遍历全文。词表总长度为 `W`、最大词长为 `L` 时，当前稀疏 failure 链构建可保守记为 `O(W × L)`，另有词表排序。扫描正文长度为 `T`，枚举候选命中为 `H候选`，每段保留命中为 `H_i`：核心成本为 `O(T + H候选 × L + Σ H_i log H_i)`；边界检查和命中排序不能省略。Markdown 解析、Unicode 归一化及原始偏移映射另计，缓存空间约 `O(T + W + H缓存)`。
3. **范围内关系生成**：复用命中，过滤源/目标、处理重叠与已选模式，再展开同名候选、汇总边和证据。可按 `O(范围条目 + 显式引用边 + 命中处理 + 候选检查/展开 + 输出证据)` 估算；很多同名目标可能放大输出，不能只看正文字数或最后的边数。预算限制结果量，但不保证候选检查量等于结果量。

当前预算见 [提及限制](../apps/siyuan-plugin/src/modules/mentions/types.ts) 和 [排除规则](../apps/siyuan-plugin/src/modules/mentions/exclusions.ts)：50,000 个关键词、词表 1,000,000 字符；单源正文 250,000 字符、256 个不同命中词、4,096 次命中；缓存 1,000,000 次命中；100,000 条提及边、每边 64 项证据；2,000 个普通排除词组和 128 个正则，各项最多 256 个 UTF-16 单元。截断会报告，不应视为完整结果。

排除规则改变会重建词表；实际词表签名没变时仍可复用命中。词表变了也保留已解析正文。
范围、投影、模式、选择变化不会重新读取笔记。预热面向已获取的整个工作区，因此缩小画面不等于同比缩小首次索引成本。

## 扩展时优先核对

[筛选结果检查](../apps/siyuan-plugin/src/core/scope/graph-explanation.ts) 使用当前建图留下的范围集合和相同的资格/投影函数，不重建图或记录所有节点的流水日志。节点和关联边索引首次构建分别为 `O(N + V)`、`O(M + E)`；热缓存下检查一个节点主要是常数次集合查询和类型判定，检查一个有向关系对则扫描原始起点及其显示代表的关联边。文本提及报告最终关系，未实现逐次正文匹配的失败追踪。

确认新功能使用原始图、当前计算图还是可见图；把相关输入加入缓存键并拒绝过期结果。
性能结论区分首次执行、热缓存、输出规模和迭代次数；不要把异步调度、输出上限或单次测量当作算法上界。
现有测量入口见 [工作区压力夹具](../scripts/stress-fixture.md) 和 [Rust 基准](../crates/graph-core/README.md)。
